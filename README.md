# Киноманьяк

Короткое видео работы телеграм бота: https://drive.google.com/file/d/1Qivjc5BJeYYJc9YI2-pi_4raj31NYFO5/view?usp=sharing 


Помощник по подбору фильмов, который рекомендует **только фильмы из собственного проверенного каталога** (`films.json`).
Модель возвращает только идентификаторы `film_id` и короткое объяснение `why`, а код проверяет каждый `id` по каталогу и печатает название, год, длительность и описание **исключительно из каталога**. Если подходящих фильмов нет — система честно отвечает `no_match`.

## Команды запуска

### 1. Установка зависимостей
```bash
uv sync
```

Создайте `.env` на основе `.env.example` и впишите ключи (см. раздел «Как получить ключи» ниже).

### 2. Подбор фильма из CLI (Common и Rare)
```bash
# Режим Common (основной контракт)
uv run kino.py "фильм как Интерстеллар, но не про космос"
uv run kino.py "Қазақша комедия керек"
uv run kino.py "мультфильм 2031 года"

# Режим Rare (извлечение Filters + фильтрация и пост-проверка кодом)
uv run kino.py --rare "что посмотреть с мамой на казахском, до двух часов"
```

### 3. Прогон набора запросов и опыт с памятью модели
```bash
# Прогон всех 30 запросов в режиме Common
uv run check.py

# Прогон всех 30 запросов в режиме Rare
uv run check.py --mode rare

# Проверка стабильности Legendary (5 прогонов подряд)
uv run check.py --mode rare --runs 5

# Опыт с памятью модели без каталога (10 фильмов)
uv run check.py --memory-test
```

### 4. Статистика по журналу `calls.jsonl`
```bash
uv run show.py
```

### 5. Автотесты и линтер (без вызова API, с заглушкой)
```bash
uv run pytest
uv run ruff check .
```

### 6. Запуск Telegram-бота (Legendary)
```bash
# С облачной моделью (из .env: OPENAI_API_KEY + MODEL + TELEGRAM_BOT_TOKEN)
uv run bot.py
```

Для запуска **бесплатно локально (путь за `$0`)** через Ollama:
```bash
ollama pull qwen3.5:4b
```
И укажите в `.env`:
```env
OPENAI_API_KEY=ollama
OPENAI_BASE_URL=http://localhost:11434/v1
MODEL=qwen3.5:4b
TELEGRAM_BOT_TOKEN=<ваш_токен_от_BotFather>
```
Затем запустите `uv run bot.py`. Для моделей с `qwen` в имени код автоматически передаёт `extra_body={"reasoning_effort": "none"}` (`kino.py:53-56`).

**Команды внутри Telegram-бота:**
- любой текстовый запрос на русском или казахском — подбор фильмов или один уточняющий вопрос (`clarify`), если запрос размытый;
- `Ещё` / `ещё` / `more` — новые фильмы по последнему запросу без повторов;
- `уже смотрел Брат` / `не показывай Титаник` — исключает указанные фильмы до конца диалога;
- `/reset` или `/start` — сбрасывает историю показанных фильмов, исключений и уточнений.

## Пять вопросов лекции 1 для задачи «Киноманьяк»

1. **Цель:** по сложному запросу на естественном языке (русском и казахском, с отрицаниями, настроением и ограничениями) подобрать от 1 до 3 фильмов **строго из закрытого каталога**, не выдумывая несуществующие названия и факты.
2. **Решение без ML:** SQL/JSON-фильтрация по точным полям (`year`, `minutes`, `genres`, `countries`, `languages`) + поиск ключевых слов по `description`. Оно бесплатно и детерминированно, но ломается на смысловых запросах вроде *«фильм как Интерстеллар, но не про космос»*, *«что посмотреть с мамой»* или *«похожее на Брат, но не российское»*.
3. **Данные и источники:** `films.json` — 47 реальных фильмов (в том числе 7 казахстанских: «Рэкетир», «Шал», «Жаужүрек мың бала», «Бизнес по-казахски», «Томирис», «Тюльпан», «Келин»). Год, длительность, страны и языки взяты из открытых источников, ссылка указана в поле `source` каждого фильма: `www.imdb.com`, `pro.imdb.com`, `en.wikipedia.org`. Жанры и страны нормализованы к русскому словарю.
4. **Что выдаёт программа с кодом:** структурированный ответ модели (`Selection` / `BotPickResponse`) проходит жёсткую валидацию в коде: проверка наличия `film_id` в переданном каталоге, отсутствие дублей, не более 3 фильмов (и соответствие `Filters` в Rare). Пользователь видит метаданные только из `films.json` + строку `why` от модели.
5. **Цена API:** для `gpt-6-luna` (ориентировочный тариф `$0.10` / 1M input и `$0.50` / 1M output) один запрос в режиме Common стоит около **`$0.00066`**, в режиме Rare — около **`$0.00034`**. Локальная `qwen3.5:4b` через Ollama — **`$0`**.

## Честная заметка о локальной модели `qwen3.5:4b` и пути за `$0`

В коде (`kino.py:53-56`, `bot.py:415`) предусмотрена полная поддержка локального запуска через Ollama (`MODEL=qwen3.5:4b`, `OPENAI_BASE_URL=http://localhost:11434/v1`, `OPENAI_API_KEY=ollama`) с обязательным `extra_body={"reasoning_effort": "none"}`, что покрыто юнит-тестами (`tests/test_kino.py`, `tests/test_bot.py`).

Честная оценка ограничений пути за `$0`:
- **Плюсы:** нулевая стоимость API (`$0`), полная приватность, работа без внешнего интернета.
- **Минусы:**
  - на 47 фильмах (~5.8k входных токенов на запрос) локальная 4B-модель на CPU работает существенно медленнее облачной `gpt-6-luna` и требует достаточного объёма RAM/VRAM;
  - компактная 4B-модель заметно чаще ошибается на сложных составных отрицаниях (*«как Интерстеллар, но не про космос»*), на казахскоязычных запросах и на строгом JSON/Structured Outputs, поэтому для `qwen3.5:4b` особенно критичны кодовая проверка `film_id` (`kino.py:239-263`) и двухшаговая фильтрация кодом (`--rare`), уменьшающая размер контекста.
- На текущей машине Ollama не установлен, поэтому все замеры в `calls.jsonl` честно выполнены на облачной `gpt-6-luna`; при переключении `.env` на локальный Ollama весь CLI и Telegram-бот работают без изменения кода.

## Ответы на 5 вопросов из раздела 9 SPEC.md

### 1. Почему программа сверяет `id`, хотя название понятнее? Сколько расхождений с каталогом дал опыт с памятью модели?
Название неоднозначно: разные фильмы могут совпадать по названию, различаться переводом, регистром, кавычками или буквой `ё` («Валли» / «ВАЛЛ-И», «Шрэк» / «Шрек»). Уникальный ключ `film_id` (`kz-01`, `f-014`) позволяет однозначно сверить ответ за `O(1)` по словарю `film_by_id` (`kino.py:295`, `kino.py:251`) и подтянуть эталонные `title`, `year`, `minutes` и `description` строго из каталога (`kino.py:266-283`).
В реальном опыте с памятью модели `gpt-6-luna` без каталога (`check.py:81-142`) получено **2 расхождения из 10 фильмов** (оба по длительности: «Рэкетир» 110 мин вместо 80 мин и «Жаужүрек мың бала» 133 мин вместо 132 мин).

### 2. Что произойдёт, если модель вернёт `film_id`, которого нет в каталоге? Какие строки кода это ловят?
Пользователь **не увидит** этот фильм. Функция `_validate_picks` (`kino.py:239-263`, конкретно проверка `if fid not in film_by_id` в `kino.py:251-253`) добавляет чужой `id` в список `rejected`. Затем в `_pick_impl` (`kino.py:356-361`) при непустом `rejected` функция записывает в `calls.jsonl` строку с `outcome="invalid"` и полем `"rejected": rejected`, печатает нейтральное сообщение об ошибке и возвращает `("invalid", [])`. Аналогичная защита в Telegram-боте стоит в `bot.py:467-492`.

### 3. Чем «модель ответила без ошибки» отличается от «модель подобрала верный фильм»? Как это видно в `check.py`?
«Ответила без ошибки» означает лишь техническую валидность: HTTP 200, JSON прошёл валидацию Pydantic, все `film_id` есть в каталоге и не дублируются (`outcome == "ok"` или `"no_match"`). Но модель всё равно может выдать неподходящий фильм (например, длиннее лимита или запрещённый условием «кроме»).
В `check.py` это разделено явно: счётчик `outcomes` (`check.py:183`, `check.py:209-213`) фиксирует технический исход, а функция `check_expectation` (`check.py:37-55`, вызов в `check.py:190-199`) проверяет смысловое качество по `expect`: `no_match`, наличие хотя бы одного `id` из `must` и отсутствие любого `id` из `forbid` — и выводит отдельную метрику `запросов с ожиданием: passed/total` (`check.py:216`).

### 4. Какое решение без ML записано в пяти вопросах лекции 1 и чего ему не хватает на запросы из `queries.json`?
Решение без ML — точная фильтрация по полям каталога (`year`, `minutes`, `genres`, `countries`, `languages`) + поиск подстрок по `description`. На запросах из `queries.json` ему не хватает понимания семантики, аналогий и контекста:
- *«фильм как Интерстеллар, но не про космос»* (нужно понять «масштабную эмоциональную фантастику» и исключить космический сеттинг по смыслу описания);
- *«что посмотреть с мамой на казахском, до двух часов»* (нужно отсеять криминальный/жёсткий контекст и перевести «до двух часов» в `<= 120`);
- *«что-то похожее на Брат, но не российское»* (поиск аналога по атмосфере криминальных 90-х, а не по слову «Брат»);
- запросы на казахском (*«Қазақша комедия керек»*, *«Екі сағаттан аспайтын қазақша драма»*) при русскоязычных описаниях в каталоге.

### 5. Сколько стоит один запрос и что сильнее всего влияет на цену?
По реальному журналу `calls.jsonl` (`show.py:68-107`):
- в режиме **Common** (`gpt-6-luna`): ~5 862 prompt-токенов + ~143 completion-токена = **~`$0.00066` за запрос** (`$0.01973` за 30 запросов);
- в режиме **Rare** (`gpt-6-luna`): в среднем ~2 471 prompt-токенов + ~195 completion-токенов на запрос (включая оба шага) = **~`$0.00034` за запрос** (`$0.01034` за 30 запросов);
- локально на `qwen3.5:4b`: **`$0`**.

Сильнее всего на цену влияет **размер каталога во входном промпте (`prompt_tokens`)**: в Common ~97.6% всех токенов (175 867 из 180 155) — это повторная отправка всего JSON-каталога на каждый запрос. Отсечение кандидатов кодом до шага выбора (как в Rare) сразу сокращает объём входных токенов более чем вдвое.

## Как получить ключи (`.env`)

Никогда не коммитьте `.env` — в репозитории хранится только шаблон `.env.example`, а `.gitignore` и pre-commit hook блокируют случайную отправку `.env`.

1. **OpenAI API (`OPENAI_API_KEY`):**
   - Зарегистрируйтесь/войдите на [platform.openai.com/api-keys](https://platform.openai.com/api-keys).
   - Нажмите **Create new secret key**, скопируйте ключ и вставьте в `.env` в поле `OPENAI_API_KEY`.
   - Задайте `OPENAI_BASE_URL=https://api.openai.com/v1` и нужную `MODEL` (например `gpt-6-luna`).
   - *(Альтернатива за `$0`: установите Ollama и используйте `OPENAI_API_KEY=ollama`, `OPENAI_BASE_URL=http://localhost:11434/v1`, `MODEL=qwen3.5:4b`.)*
2. **Telegram-бот (`TELEGRAM_BOT_TOKEN`):**
   - Найдите в Telegram официального бота `@BotFather`.
   - Отправьте команду `/newbot`, задайте имя и username бота (должен оканчиваться на `bot`).
   - Скопируйте выданный HTTP API token и вставьте в `.env` в поле `TELEGRAM_BOT_TOKEN`.
